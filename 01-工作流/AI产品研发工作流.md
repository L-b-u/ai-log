## 1. 环境搭建

- 创建对应的文件夹
- 把当前的目录初始化为一个 Git 仓库
- 创建一个 `AGENTS.md` 文件，写入下面这些内容，最后提交一个 commit

**注意事项：**

```markdown
- 每次改动完成后，都必须创建一个对应的 Git commit，以便后续追踪和回滚。
- 每次改动后，都必须编写或更新相关测试，并在交付给用户前，确保所有测试和验证全部通过。
```

## 2. 产品设计环节

- 开始用 MVP 版本，没问题后逐步往上加功能
- 中间讨论
- 最后是：

> 我同意你的建议，接下来帮我整理一份产品设计文档吧。不用太详细，把整体方向和主要功能梳理出来就可以。

在项目复杂的时候，产品设计可以设计一个 Demo，就是一个前端界面，可以直接是一个 html 文件，只包含前端逻辑，后端逻辑和数据直接模拟，主要用于体验页面的交互，哪里不对可以直接修改，直到整体体验完整为止。

**可复用指令：**

> 帮我做一个 Demo，不用实现真实的后端功能，数据模拟一下就行。我主要想先看看整体界面和操作流程是否合理。

## 3. 技术方案设计

新开一个对话，指令：

> 这个目录下有一份产品设计文档，请你读一遍这个产品设计文档，然后告诉我，用什么技术栈实现这个产品比较合适。不要给出过于详细的设计，我们先探讨一下。我听说 xxx 还可以，你怎么看？

探讨确定后，指令：

> 行，就按你说的来，现在请你写一个技术方案，放在 docs 文件夹里面。
